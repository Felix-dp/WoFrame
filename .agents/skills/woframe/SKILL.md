description: 用 WoFrame 带用户从定位走到成片：先确认赛道（泛流量、不露脸垂直、露脸个人 IP），再走对应流程——泛流量模仿爆款，垂直与 IP 走选题、文稿、成片三步——并在第一集把系列设置写进 Handbook。

运行 `node scripts/woframe.mjs doctor` 检查工具。完整流程见 [创作流程](../../../docs/creator-workflows.md)。运行命令时以 WoFrame 仓库为当前目录。

- 开工先跑 `node scripts/woframe.mjs handbooks`，看有没有同系列的沉淀。有就 `find-handbook` 找到、`apply-handbook` 合进本集，只问本集新增的东西；没有才从头问。Handbook 按赛道存在 `handbooks/<track>/<系列名>.json`，跨赛道不套用。
- 第一轮只问赛道。不要问「你是哪个赛道」，给三个场景让用户三选一：泛流量 `traffic`、不露脸垂直 `vertical`、露脸个人 IP `persona`。拿不准时按流程里的三问分流。定完写进 `track`，后面不再问。
- **Ⅰ 泛流量照着爆款做**。先问有没有想模仿的：有就问借内容、结构还是风格（可多选），收本地视频或用平台接口解析外链；没有就抓该领域近期爆款，给链接、发布日期、能核实的互动量和推荐理由，让用户选一条。选定后用 `video-use` 转录并整理借鉴项，再把参考、借鉴项和新主题交给 Hypit 生成首版，输出目录直接指向 `output/traffic/<账号名>/`（账号名没定用 `泛流量`）；只能生成到别处就用 `deliver` 移进去。交付实际产出文件和借鉴摘要。不做系列，不锁封面。
- **Ⅱ 口播出镜 / Ⅲ 不露脸共用 0-1-2**。0 收选题词：用户有成稿就先检测事实、用词和可口播性，只做局部优化，不重写不改结构；再问受众、长度节奏、平台与画幅、风格偏好。1 出初稿或差异，用户确认结构后问素材、音频（原声或 BGM）、视觉效果（字幕、画面、第一集的封面方向）。素材这一步只提醒：要交就放进 `public/work/<项目>/`，交不交、交哪些由用户定，没交就按现有素材继续。2 组装项目 JSON，跑 `check`，确认后 `render` 出片。
- Ⅲ 额外记住人设与关系、出镜规格、说话方式、表现验收，第一集定完就沿用，不每集重问。
- Ⅱ/Ⅲ 先多选平台与发布入口、确定主发入口和内容形式，再设置画幅；Ⅰ 只确认主发平台，画幅和封面在 Hypit 出片时定，不写 `publishingTargets`。按 [视频画幅与封面指南](../../../docs/publishing-formats.md) 推荐视频和封面各自的画幅、像素及封面来源。用户已明确的规格直接沿用。成片后检查封面裁切，交付 MP4 和可上传的封面图，或给出选帧时间点。
- Ⅱ/Ⅲ 第一集定封面方向：按 [封面风格](../../../docs/cover-styles.md) 给可选方向和样品，选定后写 `coverStyle`。后续集沿用同一套版式，只换标题、钩子和图。
- 第一集成片出来后自动用 `save-handbook` 沉淀，不用再问一轮：命令把这一集问到的答案写进 `handbooks/<track>/<系列名>.json`，同名时合并写入，已有字段不会丢。系列名没定就用本集标题命名。
- 成片用 `render` 直接写到 `output/<track>/<系列名>/`，文件名由命令生成，不手写。封面图用 `deliver --cover` 放进同一目录。
- 将项目与素材放进 `public/work/` 的同一个子目录，出片前用 `node scripts/woframe.mjs check <项目.json>` 查缺失素材和无效时间轴。`check` 报音画时长对不上时跑 `fit <项目.json> --write` 按音频重算帧数，不要自己心算。`render` 出片后由用户在当地播放验收，通过才算完成；要逐镜核对细节可以用 `npm run preview`。
