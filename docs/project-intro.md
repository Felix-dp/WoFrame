# WoFrame（一帧）· 项目介绍

> 一个把"我想做视频"变成"这条可以发"的 Agent 工作流仓库。

## 一、项目介绍

WoFrame 是面向短视频创作者的 Agent 工作流框架。它不是网站，也不是 App，而是一个可以直接 `git clone` 的 GitHub 仓库：用户在本机克隆后，用 Codex、Claude Code 等能读取 `AGENTS.md` 的 Agent 打开，Agent 就会按仓库里写好的流程，一步一步把用户从模糊的想法带到一条能发布的成片。

它要解决的是一段真实的断层。一个想做知识视频的人，真正卡住的往往不是"不会剪"，而是：我该做哪个赛道、这一集讲什么、脚本怎么写、素材从哪来、竖屏还是横屏、封面长什么样、下一集怎么不重复回答同样的问题。这些判断散落在经验、教程和十几个互不相通的工具里，第一次做的人几乎必然在中途放弃。

WoFrame 把这些判断收进一套可执行的流程，并把它拆成三条赛道：

| 赛道 | 用户是谁 | 走哪条路 |
| --- | --- | --- |
| Ⅰ 泛流量 | 追热点、账号未定型 | 照着爆款做：参考片 / 抓近期爆款 → video-use 拆解 → Hypit 生成 |
| Ⅱ 不露脸垂直 | 有专业、不想出镜、要做系列 | 选题 → 文稿 → 成片（0-1-2 三步） |
| Ⅲ 露脸个人 IP | 卖的是"这个人" | Ⅱ 的全部，另加人设、出镜规格、说话方式、表现验收 |

Ⅱ 和 Ⅲ 共用同一条主干，只在"人"的部分分叉。第一集确认过的选择会沉淀成该系列的 Handbook；下一次开工，Agent 先查 Handbook，只问这一集新增的问题，不再从头盘问。

## 二、核心功能

1. **赛道定位**：第一轮只问一件事——账号靠什么活下去。给三个具体场景让用户选，而不是让用户理解"赛道"这个词；拿不准时用三个问题分流。
2. **两条生产流程**：泛流量走"模仿爆款"的快速链路；垂直与 IP 走"选题 → 文稿 → 成片"的三步链路。两条链路的成片引擎不同，分工明确。
3. **系列沉淀**：每份 Handbook 按赛道存放在 `handbooks/<赛道>/<系列名>.json`，第一集成片后自动生成；同名时合并写入，不会覆盖已有设定。开工先查、命中就复用。
4. **项目即配置**：一集视频就是一个 `episode.json`——画幅、分镜、字幕、配音、BGM 全在里面，可版本管理、可回滚、可复用。
5. **规范出片**：`render` 通过无头渲染直接产出 MP4，写入 `output/<赛道>/<系列名>/EP01-标题-9x16.mp4`，文件名由命令生成，不靠人手写。
6. **质量闸门**：`check` 校验素材缺失、时间轴与配置合法性；`fit` 读取音频真实时长并重算帧数，解决"渲染完才发现音画差半秒"。
7. **封面体系**：五套风格模板（简·色块、科技·霓虹、电影·学术、切片·信息条、纸感·编辑），一套模板同时适配 16:9、3:4、4:3、1:1。
8. **发布规格**：按平台与发布入口生成 `publishingTargets`，确定主发入口、视频画幅与封面画幅，一稿多发时同画幅共用导出版本。

## 三、技术亮点

- **仓库即产品，Agent 即前端**。产品形态不是网页，而是 `AGENTS.md` + `SKILL.md` + 一套确定性 CLI。任何支持读取仓库指令的 Agent 都能接入，用户不需要打开任何网站。
- **可验证的命令边界**。流程里的每一步都落到一条命令：`doctor` 查环境、`check` 查素材、`fit` 对齐音画、`handbooks`/`find-handbook` 检索沉淀、`save-handbook` 合并写入、`render` 出片。每一步都有输出、可复现、可回滚，不依赖"Agent 记住了"。
- **双引擎分工**。系列内容用 Remotion：版式可控、多画幅一致、可逐帧检查；追热点用 Hypit：从参考片直接生成首版。两者产物都收敛到同一套 `output/` 目录规范。
- **文件系统即数据库**。系列沉淀按赛道分目录，成品按赛道和系列分目录，命名由命令生成。用户转型换赛道时，旧 Handbook 留在原目录，不串味、不误用。
- **音画对齐自动化**。用 ffprobe 读每段音频的真实时长，反推该镜应有的帧数，而不是让 Agent 心算 `frames = 秒 × fps`。
- **模板级设计系统**。封面用容器查询单位排版，同一份 HTML 模板在不同画幅下重排而非缩放，竖版不是横版的缩小版。
- **本地优先**。素材、项目、成品、凭据全部留在本机；官方仓库里 `handbooks/` 与 `output/` 都是空的，用户克隆后沉淀的系列和产出的成片只存在于他自己的仓库副本，`public/work/` 与 `output/` 不对上游提交。
